# Kansas 算例极详细设置

本文档从 `case_run_details_zh.md` 分离而来, 专门记录 `Kansas` 算例的完整运行设置。

返回主文档: [Example input 算例运行情况详细说明](case_run_details_zh.md)

## 4. Kansas

### 文件与总体设计

- 参数表: `Kansas/kansas inputs.xlsx`
- 天气文件: `Kansas/KansasWea.csv`
- 运行数: 13
- 地点: `Ashland`, `Cullison`, `Hutchingson`, `Manhattan`, `Moscow`
- 天气尺度:
  - `AshDry`, `AshIrr`: `Weather` 表标为 `hourly`
  - `Cullison`, `Moscow`, `Manhattan`, `Hutchingson`: `Weather` 表标为 `daily`
- `Time` 表:
  - 所有 run 的 `Daily=0`, `Hourly=1`
  - `WeatherDaily/WeatherHourly` 随 WeatherID 不同而不同: 非 Ashland 站点为 `WeatherDaily=1`, `WeatherHourly=0`; Ashland 为 `WeatherDaily=0`, `WeatherHourly=1`
- 气体参数: 全部使用 `GasCO2Default`, `GasO2Default`, `GasN2ODefault`
- 目录中有 `Kansas_wea(output files for sims).zip`, 其中包含 10 个已生成的 `.wea` 文件: `ASHD05.wea`, `ASHD06.wea`, `ASHI05.wea`, `ASHI06.wea`, `CULI05.wea`, `CULI06.wea`, `HUTD06.wea`, `MAND06.wea`, `MOSI05.wea`, `MOSI06.wea`。
- `ASHD06IR`, `CULI05IR`, `MOSI06IR` 没有单独的 `.wea` 文件, 它们在 `Description` 表中分别复用 `ASHD06.wea`, `CULI05.wea`, `MOSI06.wea`。

### 运行间主要修改点

- 站点差异是第一层变化: 每个站点有不同的 `ClimateID`, `WeatherID`, 坐标, 土壤文件和品种。
- 非 Ashland 站点使用日天气源, 但 `Time` 表仍设置 `Hourly=1`; 区分天气尺度的关键字段是 `WeatherDaily/WeatherHourly`。
- `MAND06` 使用的 `Manhattan` 日天气只覆盖到 2006-10-22, 短于 `Time.EndDate=2006-11-01`; 这在正式运行或数据同化前需要优先核查。
- `MOSI05` 的模拟期内包含 `Moscow` 天气在 2005-07-03 的重复日记录, 其期内天气行数为 236 行而不是 235 行; 若模型天气读取器要求每天唯一记录, 也需要核查。
- Ashland 有最清晰的 dry/irrigated 对照:
  - `ASHD05` vs `ASHI05`: 同年, 同品种, 同土壤 `Eudora.soi`, 主要改变 `WeatherID`, 施肥和灌溉记录。
  - `ASHD06` vs `ASHI06`: 同年, 同品种, 同土壤 `Belvue.soi`, 主要改变 `WeatherID`, 种植密度略有差异, 施肥日期和灌溉记录不同。
- `ASHD06IR`, `CULI05IR`, `MOSI06IR` 是额外显式灌溉运行, 与其对应基础运行共享品种, 土壤, 天气文件和大部分管理设置, 但灌溉从 `Irrig_data` 转为 `Irrig` 表规则。
- `MOSI06IR` 的第一条 `Irrig` 记录为 2006-05-05 到 2005-05-10, 日期明显异常。若要正式运行或用于研究, 必须先核查该行是否应改为 2006-05-10 或其它日期。
